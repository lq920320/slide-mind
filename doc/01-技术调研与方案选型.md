# SlideMind 技术调研与方案选型

> 目标：开发一个开源桌面软件，核心能力为「思维导图 + 幻灯片演示」，
> 类似 XMind 的 Pitch 演示模式：从思维导图的分支结构自动生成幻灯片并演示。
> 技术基座：Rust + Tauri + Web 前端。

## 1. 产品形态分析（对标 XMind Pitch）

XMind 演示模式的本质流程：

```
思维导图（节点树） ──选择分支──▶ 幻灯片大纲（每个节点/分支 = 一页） ──▶ 渲染演示
```

由此拆出三个核心子系统：

| 子系统              | 职责                                     | 关键技术点                         |
| ------------------- | ---------------------------------------- | ---------------------------------- |
| 导图编辑器          | 节点增删改、拖拽、样式、快捷键、撤销重做 | 开源思维导图库                     |
| 导图 → 幻灯片转换器 | 节点树遍历 → 幻灯片大纲（Markdown/JSON） | 自研核心逻辑（本项目的差异化价值） |
| 演示渲染器          | 幻灯片渲染、翻页、演讲者视图、导出       | Slidev / reveal.js                 |

## 2. 开源思维导图库选型

### 候选对比

| 库              | 协议            | 维护状态                              | 框架依赖                 | 可编辑                         | 数据结构     | 生态                                             |
| --------------- | --------------- | ------------------------------------- | ------------------------ | ------------------------------ | ------------ | ------------------------------------------------ |
| **mind-elixir** | MIT             | ✅ 活跃（v5）                         | 无（framework-agnostic） | ✅ 完整交互编辑                | 简洁 JSON 树 | node-menu、export-xmind、export-html、react 封装 |
| simple-mind-map | MIT（仅 JS 库） | ⚠️ 官方声明「低维护状态」，客户端闭源 | 无（示例基于 Vue2）      | ✅ 功能最全                    | JSON 树      | 功能多但依赖单一作者                             |
| jsMind          | BSD-3           | 维护缓慢                              | 无                       | ✅ 基础编辑                    | JSON 树      | 较弱                                             |
| markmap         | MIT             | 活跃                                  | 无                       | ❌ 只读渲染（Markdown → 导图） | Markdown     | VSCode 插件等                                    |

### 结论：选择 mind-elixir

理由：

1. **MIT 协议**，与开源桌面软件目标一致，无授权风险。
2. **框架无关 + 插件化架构**，可以自由搭配 Vue3/React，且可通过 `mind.install(plugin)` 扩展「演示模式」入口。
3. **数据结构简洁**（`{ topic, id, children, style, image, hyperLink, ... }` 的纯 JSON 树），非常适合做「导图 → 幻灯片」的转换源。
4. **事件总线完善**（`operation` / `selectNodes` 等），方便实现自动保存、选中分支生成幻灯片等交互。
5. **生态契合**：官方生态已有 `@mind-elixir/export-xmind`（导出 XMind 格式）、`@mind-elixir/node-menu`（节点属性面板），能显著减少工作量。
6. 已被 Mind Elixir Desktop 等桌面产品验证过可行性。

不选 simple-mind-map 的原因：虽然功能最全，但作者已将重心转向闭源客户端，
JS 库进入低维护状态，长期依赖风险高；且其 Web 端绑定 Vue2 + ElementUI，技术栈偏旧。

markmap 的定位补充：它不适合做编辑器，但其「Markdown ↔ 导图」的思路
可作为本项目大纲导入/导出功能的参考。

## 3. 幻灯片引擎选型：Slidev 的集成难点与策略

### 3.1 Slidev 架构特点

- Slidev 是 **Markdown 驱动** 的演示工具（`slides.md`，`---` 分页）。
- 运行时依赖 **Node.js + Vite**：`slidev dev` 启动开发服务器，`slidev build` 产出静态 SPA，`slidev export` 导出 PDF/PPTX/PNG。
- **无法作为纯浏览器端 JS 库直接嵌入** Tauri 的 WebView —— 这是集成的核心矛盾。

### 3.2 三种集成方案对比

| 方案                                     | 说明                                                                                                                          | 优点                                                 | 缺点                                                                 |
| ---------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------- | -------------------------------------------------------------------- |
| A. Node sidecar 内嵌 Slidev              | Tauri sidecar 打包 Node 运行时（或用 Bun 单文件编译），应用内启动 `slidev dev/build`，WebView 加载其本地服务                  | 100% Slidev 能力（动画、代码高亮、演讲者视图）       | 安装包体积 +80~100MB；进程管理复杂；首次启动慢；跨平台打包 Node 麻烦 |
| B. 外部依赖用户环境 Node                 | 检测用户机器上的 Node，调用 `npx slidev`                                                                                      | 实现简单，包体积小                                   | 桌面软件要求用户装 Node，体验差，不可接受为主路径                    |
| C. 内置轻量渲染器 + 导出 Slidev Markdown | 应用内用 **reveal.js（MIT，纯前端库）** 渲染演示；同时把幻灯片导出为标准 Slidev `slides.md`，供高级用户用 Slidev 工作流深加工 | 零运行时依赖、体积小、秒开演示；仍然打通 Slidev 生态 | 应用内演示效果不是 Slidev 原生（但 reveal.js 足够强）                |

### 3.3 结论：C 为主路径，A 为可选增强

**MVP 采用方案 C**：

```
mind-elixir JSON 树
      │
      ▼  转换器（核心自研，Rust 或 TS 实现）
幻灯片中间模型（SlideDoc JSON）
      │
      ├──▶ reveal.js 应用内即时演示（F5 一键演示，无外部依赖）
      ├──▶ 导出 slides.md（Slidev 兼容格式，含 frontmatter/分页/布局注记）
      └──▶ 导出 PDF/PNG（Tauri 端打印 / 截图）
```

**v2 增强（可选）采用方案 A**：提供「Slidev 增强包」按需下载 sidecar
（用 Bun `bun build --compile` 把 Slidev CLI 编成单文件二进制，规避完整 Node 分发），
在应用内直接获得 Slidev 原生演示与 `slidev export` 的 PPTX 导出能力。

这样既尊重了「基于 Slidev」的初衷（格式兼容 + 可选原生集成），
又保证了桌面软件该有的开箱即用体验。

## 5. 关键设计决策

### 5.1 文件格式 `.smind`

单文件 JSON（后续可升级为 zip 容器以内嵌图片资源）：

```jsonc
{
  "version": 1,
  "meta": { "title": "...", "createdAt": "...", "updatedAt": "..." },
  "mindmap": {/* mind-elixir getData() 原始 JSON */},
  "slides": {
    "config": { "theme": "default", "aspectRatio": "16/9" },
    "pages": [{ "nodeId": "xxx", "layout": "section", "notes": "...", "hidden": false }],
  },
}
```

要点：**幻灯片页与导图节点通过 `nodeId` 关联**，导图修改后幻灯片自动跟随更新；
`slides.pages` 只存编排信息（顺序、布局、备注、跳过），内容始终以导图为唯一数据源
（single source of truth），这正是 XMind Pitch 的核心体验。

### 5.2 导图 → 幻灯片转换规则（默认策略）

1. 根节点 → 封面页（title layout）。
2. 每个一级分支 → 章节页（section layout）。
3. 每个二级节点 → 内容页，其子节点渲染为 bullet list（默认展开到 2 层）。
4. 节点包含图片 → image 布局；包含超链接/备注 → 渲染为页脚注记。
5. 用户可在编排面板中：调整页序、合并/拆分、隐藏分支、覆写布局。

### 5.3 Slidev Markdown 导出映射

```markdown
---
theme: default
title: <根节点 topic>
---

# <根节点 topic> ← 封面

---

layout: section
---

# <一级分支 topic> ← 章节页

---

# <二级节点 topic> ← 内容页

- <三级节点 topic>
- <三级节点 topic>
```

### 5.4 XMind 文件导入

`.xmind` 是 zip 容器（内含 `content.json`），Rust 端用 `zip` + `serde_json`
解析并映射为 mind-elixir 数据结构，实现从 XMind 迁移。
导出 XMind 则直接复用 `@mind-elixir/export-xmind`。

## 6. 风险与对策

| 风险                                                | 影响                               | 对策                                                               |
| --------------------------------------------------- | ---------------------------------- | ------------------------------------------------------------------ |
| mind-elixir v5 API 变动                             | 编辑器返工                         | 封装 adapter 层，业务代码不直接触碰其 API                          |
| Slidev 无法嵌入的预期落差                           | 演示效果与 Slidev 官网 demo 有差距 | 文档明确「内置演示 + Slidev 导出」双轨定位；v2 提供 sidecar 增强包 |
| reveal.js 与导图主题风格不统一                      | 观感割裂                           | 自定义 reveal.js 主题，与导图主题色板打通                          |
| 大图（数千节点）性能                                | 卡顿                               | mind-elixir 本身为大图优化；幻灯片生成用增量计算                   |
| 跨平台 WebView 差异（WKWebView/WebView2/WebKitGTK） | 渲染不一致                         | CI 三平台构建 + 冒烟测试；避免使用前沿 CSS 特性                    |
