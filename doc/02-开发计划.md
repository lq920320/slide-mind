# SlideMind 开发计划（阶段拆分）

> 前置阅读：[01-技术调研与方案选型.md](./01-技术调研与方案选型.md)
>
> 总体节奏：6 个阶段，M0~M5。每个阶段结束都有可运行、可验收的产物。

## 里程碑总览

| 阶段 | 名称              | 核心产物                                | 预估工作量 |
| ---- | ----------------- | --------------------------------------- | ---------- |
| M0   | 项目脚手架        | 可运行的 Tauri + Vue3 空壳应用，CI 就绪 | 0.5~1 周   |
| M1   | 思维导图编辑器    | 完整可用的导图编辑 + 本地文件读写       | 2~3 周     |
| M2   | 导图 → 幻灯片核心 | SlideDoc 转换器 + 大纲编排面板          | 2 周       |
| M3   | 演示模式          | reveal.js 全屏演示、演讲者备注          | 1~2 周     |
| M4   | 导入导出与互操作  | Slidev md / XMind / PDF / 图片          | 2 周       |
| M5   | 打磨与发布        | 三平台安装包、自动更新、官网            | 1~2 周     |

---

## M0：项目脚手架（0.5~1 周）

**目标**：搭好工程骨架，团队/社区成员 clone 后一条命令跑起来。

- [x] `pnpm create tauri-app`：Tauri 2.x + Vue 3 + TypeScript + Vite 模板初始化
- [x] 目录结构规划：
  ```
  slide-mind/
  ├── src/                  # Vue 前端
  │   ├── components/       # 组件
  │   ├── stores/           # Pinia
  │   ├── core/             # 领域核心：SlideDoc 模型、转换器（纯 TS，可单测）
  │   └── views/            # 编辑器视图 / 演示视图
  ├── src-tauri/            # Rust 后端
  │   └── src/
  │       ├── commands/     # invoke 命令：文件、导出、导入
  │       └── fs/           # .smind 读写、备份
  ├── doc/                  # 本目录
  └── e2e/                  # 端到端测试
  ```
- [x] 工程规范：ESLint + Prettier + rustfmt + clippy（husky pre-commit 待补）
- [x] 单测框架：Vitest（前端/core）、`cargo test`（Rust）
- [x] GitHub Actions：三平台（macOS/Windows/Linux）构建冒烟
- [x] 搭出主窗口框架：工具栏 / 中央画布区 / 左侧大纲面板（未引入 Naive UI，先用手写样式保持轻量）

**验收**：`pnpm tauri dev` 打开空白主窗口；CI 三平台绿。

## M1：思维导图编辑器（2~3 周）

**目标**：达到"日常可用"的导图编辑体验，文件能存能开。

### 1.1 编辑器集成

- [x] 集成 mind-elixir v5，封装 `MindMapAdapter`（隔离第三方 API，见调研文档 §6 风险项）
- [x] Vue 组件包装：`<MindCanvas>`，生命周期管理（init/refresh/destroy）
- [ ] 接入 `@mind-elixir/node-menu`（节点样式面板）或自研右侧属性面板
- [x] 主题系统：内置 4 套主题（默认/暗色/暖阳/森林），通过 mind-elixir `theme` API 切换

### 1.2 文档与文件（Rust 端）

- [x] 定义 `.smind` v1 格式（JSON，含 `mindmap` + `slides` 两段）
- [x] Tauri commands：`read_document` / `write_document` / `get_recent_files` / `add_recent_file`
- [x] 脏标记 + 自动保存（监听 mind-elixir `operation` 事件，防抖 3s）
- [x] 崩溃恢复：写入前备份 `.smind.bak`，临时文件 + rename 原子写入
- [x] 系统集成：文件关联 `.smind`、最近文件菜单、未保存关闭提醒

### 1.3 编辑体验

- [x] 快捷键梳理（mind-elixir 内置 Tab/Enter/F2/撤销重做 + 自定义 ⌘S 保存 / ⇧⌘S 另存 / ⌘O 打开 / ⌘F 搜索）
- [x] 大纲视图（左侧树形列表，点击定位画布节点；画布→大纲反向高亮待补）
- [x] 节点搜索（Cmd/Ctrl+F 定位节点，结果展示祖先路径）

**验收**：新建 → 编辑百节点导图 → 保存 → 重开无损；断电场景可从 .bak 恢复。

## M2：导图 → 幻灯片核心（2 周）★ 差异化价值所在

**目标**：实现 XMind Pitch 式的"一键从导图生成幻灯片"。

### 2.1 SlideDoc 中间模型（纯 TS，`src/core/`）

- [x] 定义 `SlideDoc` / `SlidePage` 渲染模型 + `SlidesSection` / `SlidePageMeta` 编排持久化模型（页 ↔ 节点 `nodeId` 关联）
- [x] 转换器：`syncSlides`（增量同步）+ `buildSlideDoc`（渲染计算）+ `mindToSlides`（一键默认生成），默认规则：
  - 根节点 → 封面页；一级分支 → 章节页；二级节点 → 内容页（子节点为 bullets）
  - 图片节点 → image 布局；备注 → speaker notes
- [x] 增量同步：导图变更后按 `nodeId` diff 更新，保留用户的顺序/布局/备注/隐藏覆写；分支 rootId 失效自动回退整图
- [x] 完整单测覆盖转换/同步/覆写规则（12 个用例）

### 2.2 幻灯片编排面板

- [x] 底部缩略图条：HTML 缩放渲染，区分封面/章节/内容/图片四种版式
- [x] 编排操作：拖拽调序、隐藏页、改布局（自动/封面/章节/内容/图片）、编辑演讲备注；另支持重新生成
- [x] "从选中分支生成"：选中节点 → 面板按钮生成（rootId 机制），可一键恢复整图
- [x] 双向定位：点缩略图 → 导图聚焦节点；画布选中成页节点 → 缩略图高亮滚动

**验收**：任意导图一键生成结构合理的幻灯片序列；改导图节点文字，幻灯片同步更新且不丢编排。

## M3：演示模式（1~2 周）

**目标**：F5 一键进入全屏演示，体验对齐主流演示软件。

- [x] 集成 reveal.js 6：`PresentationView` 将 SlideDoc 渲染为 reveal 页面（四种布局版式），自定义暗色主题与应用主色对齐
- [x] 全屏演示：当前窗口覆盖层 + Tauri `setFullscreen`（浏览器环境降级为 Fullscreen API）；工具栏 ▶ 演示按钮 + F5 快捷键
- [x] 翻页控制：方向键/空格/点击；页码指示（c/t）+ 进度条；Esc 退出；隐藏页自动跳过
- [x] 演讲者视图（应用内 HUD，N 键切换）：备注 + 下一页预览 + 计时器；双屏第二窗口独立演讲者视图待后续增强
- [x] 演示中的渐进展示：内容页 bullets 逐条出现（reveal.js fragments）
- [ ] 激光笔/画笔标注（可选，reveal.js 插件）

**验收**：双屏环境下，主屏放映、副屏演讲者视图，20 页演示流畅无卡顿。

## M4：导入导出与互操作（2 周）

**目标**：打通 Slidev 与 XMind 生态，兑现"开放格式"承诺。

### 4.1 导出

- [x] **Slidev Markdown 导出**（核心）：`slideDocToSlidevMarkdown`，headmatter（theme/title）+ `layout:` 注记（cover/section/image）+ speaker notes（`<!-- -->` 语法）；隐藏页不导出；图片资源文件夹待补
- [x] PDF 导出：离屏渲染逐页 → snapdom 栅格化 → jsPDF 合成 16:9 横向文档 → Rust 写入（base64）
- [x] PNG 批量导出：逐页截图到所选目录（2x DPR 高清）
- [ ] 导图导出：PNG / SVG（mind-elixir 能力）、XMind（`@mind-elixir/export-xmind`）、Markdown 大纲

### 4.2 导入

- [x] XMind 导入：Rust `zip` 解包 `content.json` → `xmindToMind` 转换（XMind 2020+ 格式；href 映射超链接；图片资源暂不导入）
- [ ] Markdown 大纲导入：`#`/`-` 层级 → 导图树（参考 markmap 的解析思路）
- [ ] FreeMind `.mm` 导入（可选，XML）

**验收**：导出的 slides.md 在官方 `slidev` CLI 中可直接运行且版式正确；主流 .xmind 文件导入后结构无损。

## v2 展望（发布后迭代方向）

| 方向                     | 说明                                                                                  |
| ------------------------ | ------------------------------------------------------------------------------------- |
| Slidev 增强包（sidecar） | Bun 单文件编译 Slidev CLI，应用内原生 Slidev 演示 + PPTX 导出（调研文档 §3.3 方案 A） |
| `.smind` zip 容器化      | 内嵌图片附件，单文件分发                                                              |
| 演示录制                 | 录屏 + 旁白导出视频                                                                   |
| AI 辅助                  | 大纲生成导图、演讲备注润色（接本地/云端 LLM）                                         |
| 协作                     | 基于 CRDT（yjs/loro）的多人编辑                                                       |

## 开发顺序上的两条建议

1. **`src/core/`（SlideDoc 模型 + 转换器）保持零依赖纯 TS**，不 import Vue/Tauri/mind-elixir，
   便于单测与未来复用（如做 CLI、Web 版）。
2. M2 做完就可以发预览版吸引社区反馈——"导图一键变幻灯片"是最能打动人的时刻，
   不必等 M4 全部完成。
